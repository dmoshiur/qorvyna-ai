# AI provider routing and reliability

Automatic pools prefer GPT OSS 120B then GPT OSS 20B, followed by available Cloudflare GLM and other specialists (maximum four); availability depends on credentials and model catalog/probe. Task-specific collaboration can assign specialists by strengths. Users can select a manual pool in Models. No latency comparison of live services was performed.

Cloudflare previously led every artifact request because `resolvePool` explicitly prepended the artifact tier, while the registry gave GLM coordinator rank 0. That was a policy decision, not measured evidence. Automatic artifact pools now prefer 120B and GLM's coordinator rank is lower; manual choices and the existing Cloudflare quota gate remain.

`QORVYNA_GROQ_LATENCY_BUDGET_MS`, `QORVYNA_CLOUDFLARE_LATENCY_BUDGET_MS`, `QORVYNA_OPENAI_LATENCY_BUDGET_MS` set the non-streaming answer / first visible stream-output deadline (1,000–180,000 ms; defaults 60s, 20s, 60s). After visible output, an idle watchdog is 60s; aggregated build streams also have an overall cap. The executor also bounds callers when an adapter ignores its abort signal; cleanup is best-effort and an uncooperative underlying operation can continue consuming resources until the transport ends. Adapters should still honor cancellation. A timeout before visible output permits orchestrator fallback; after visible output the error and partial answer are preserved and no restart occurs. User cancellation is not a fallback. Streaming completion can still be slow when continuously producing output.

Groq reads available rate-limit headers and Retry-After; unknown numbers are not filled in as remaining quota. The in-memory scheduler is a local token policy, not provider billing data. Its provider cooldown uses Retry-After where available; otherwise 30s. Pooled Groq chat also shares conservative model rate state across workers using Firestore; all keys with unknown organization identity are grouped together. Direct non-pooled calls do not participate. See [GROQ_CREDENTIAL_POOL.md](GROQ_CREDENTIAL_POOL.md). Cloudflare keeps its existing Firestore/analytics-based quota policy (`cloudflare-quota.ts`).

The UI status indicator does not automatically poll inference; it learns from successful responses. Both public health endpoints report AI configuration as unknown without performing inference. An authenticated explicit model check or operator provider test can still consume quota. The existing OpenAI-compatible health cache and Groq error pauses are not a distributed latency-aware circuit breaker. There is no fleet-wide provider health dashboard or P50/P95 analysis in this change.
